# Pinned Solidity execution fixtures

[`Contracts.sol`](../src/execution/fixtures/solidity/Contracts.sol) contains a counter and a minimal ERC-20. The counter starts at 41 and increments to 42. The token constructor mints 1,000 units to the deployer, then a transfer moves 75 units and a second transfer of 2,000 reverts with ABI-encoded `insufficient balance`. Neither contract calls a precompile. This token deliberately implements only the methods needed for execution coverage.

[`compiler-input.json`](../src/execution/fixtures/solidity/compiler-input.json) pins Solidity `0.8.28+commit.7893614a`, optimizer enabled with 200 runs, and Shanghai EVM output. [`artifacts.json`](../src/execution/fixtures/solidity/artifacts.json) contains the compiler's ABI, creation bytecode, runtime bytecode, and metadata. [`reference.json`](../src/execution/fixtures/solidity/reference.json) pins SHA-256 hashes of source, compiler input, and both bytecodes, plus signed transactions and independent Geth v1.17.10 expectations for gas, receipt status, logs, state root, and receipts root. The fixture tests read these files directly; CI needs neither solc nor Geth.

To reproduce the compiler output, run Solidity 0.8.28's standard JSON compiler on `compiler-input.json` and select the `contracts.Contracts.sol` object. To reproduce the execution oracle, feed `reference.json`'s signed transactions as one RLP list into `evm t8n --state.fork Shanghai` from Geth v1.17.10. Use a genesis allocation of 1,000,000,000 wei for private key `0x01`'s address, block number and timestamp 1, gas limit 30,000,000, base fee 1, zero random value and parent hash, coinbase `0x33` repeated 20 bytes, and empty withdrawals. The source and bytecode hashes protect against accidental compiler drift.

The direct transition test checks the Geth values and storage changes. The production service integration test submits the same signed transactions through `eth_sendRawTransaction`, builds and imports Engine payloads, checks canonical receipts, logs, calls, and traces, then restarts the service and repeats historical reads. It runs the Shanghai bytecode under the service's Osaka fork, so Osaka gas and state roots are validated by Engine rather than compared to the Shanghai oracle. No unsupported compiler output was observed for these contracts. They make no precompile calls; precompile coverage remains in #90.
