# Fulu P2P wire payloads

`consensus.P2PWire` handles byte payloads after SSZ serialization and before transport. It exposes the pinned request protocol prefixes for Status v2, Ping v1, Metadata v3, block by root/range v2, and data columns by root/range v1. `topicName` formats block, attestation, aggregate, and data-column gossip topics from the caller's fork digest and rejects invalid subnet numbers.

`encodeGossip` and `decodeGossip` use Snappy blocks with the 10 MiB uncompressed payload limit and a caller-supplied encoded-size cap. `encodePayload` and `decodePayload` use an unsigned protobuf varint for the uncompressed SSZ length, followed by Snappy stream frames. The decoder checks the length and encoded-size caps before allocating output, then verifies frame sizes, CRC32C checksums, and exact output length. The caller passes the SSZ type's maximum size. The writer uses valid uncompressed Snappy frames; the reader accepts both compressed and uncompressed frames.

`encodeResponseChunk` and `decodeResponseChunk` wrap one complete payload with its result code. Successful block and column chunks require a four-byte fork digest. If the slot is known, callers can pass its expected digest for an early check. If the slot is unknown, callers pass `null` and receive the wire digest in `ResponseChunk.fork_digest`; they must check it against the decoded object's slot before accepting the response. Use a size cap covering the permitted fork types when decoding an unknown slot. Error chunks have no fork context and contain at most 256 message bytes. Unknown response codes and unexpected resource-unavailable results are rejected.

`ResponseStream` accepts arbitrarily split network reads, bounds its pending bytes to 16 MiB, and yields one response chunk at a time. The caller frees each returned payload. `consensus.P2PIngress` decodes Fulu block and attestation gossip, checks the topic digest against the decoded slot, and then calls the caller's consensus validator. It also checks a column's topic digest, subnet, and known block before using the verified column store. `decodeBlockResponse` checks a returned block's decoded slot against the wire digest. The caller must validate consensus rules before forwarding gossip or importing blocks.

`consensus.P2PRequests` decodes bounded block and column requests, delegates lookups to the retained block view and verified column store, and returns one fork-scoped response chunk per item. Unknown roots yield no chunks and do not change state. The caller frees `EncodedChunks` with `deinit`. The live responder accepts the pinned request schema limits of 128 blocks and 128 column indices per block. It serves at most 128 sidecars and 15 MiB of raw sidecar bytes in one response, preserving complete blocks in range responses; block responses also stop at 15 MiB. Larger requests can be split by the caller.

`consensus.P2PControl` encodes and decodes the pinned Status v2, Ping v1, and Metadata v3 SSZ requests and successful response chunks in bounded Req/Resp Snappy framing. Status includes Fulu's earliest available slot; the live peer compares its fork digest before opening gossip. The caller checks finalized-chain compatibility before using a peer's head. Ping carries a metadata sequence number, while Metadata carries attestation and sync subnet bits plus the custody group count. The live peer checks the count against the signed ENR.

`consensus.P2PMultistream` negotiates `/noise`, `/yamux/1.0.0`, `/meshsub/1.1.0`, and the exact `ssz_snappy` Req/Resp IDs through multistream-select 1.0. An initiator sends `offer`; a responder echoes the header and either the supported protocol or `na`. Both state machines accept split transport reads and return the number of bytes consumed. Negotiation lines are limited to 128 bytes, including the newline. `/noise` is selected on TCP before authentication; all later selections run inside Noise.

`consensus.P2PGossipSession.Session` binds one transport-authenticated peer ID to an initiator or responder gossip stream. The initiator writes `opening`; each side calls `feed` until the negotiation response and local subscription frame have been written, then `feed` routes subsequent bytes to `P2PGossip.Stream`. `Result.consumed` identifies any unread bytes after a negotiation event, and `Result.deinit` releases its caller-owned output. Only one session per peer may use a `P2PGossip.Service` at a time. `Session.deinit` drops partial stream bytes and remote subscriptions while preserving the peer's invalid-message score. Invalid negotiation framing counts toward that score. The caller supplies authenticated stream I/O and a read deadline.

`consensus.P2PNoiseIdentity` encodes the secp256k1 libp2p public key and a low-S DER signature over `noise-libp2p-static-key:` plus the 32-byte Noise static public key, following the [libp2p Noise](https://github.com/libp2p/specs/blob/master/noise/README.md) and [peer identity](https://github.com/libp2p/specs/blob/master/peer-ids/peer-ids.md) specifications. `verify` accepts a decrypted handshake payload only when its canonical identity key matches a previously verified ENR and the signature binds that Noise key. Optional Noise extension bytes are ignored after bounded framing; payloads are capped at 1,024 bytes. The caller must verify the signed ENR and complete Noise XX before admitting stream data.

`consensus.P2PNoiseXX` implements the three-message `Noise_XX_25519_ChaChaPoly_SHA256` handshake after `/noise` is negotiated on TCP. `P2PTcp` supplies fresh static and ephemeral X25519 keys, verifies the decrypted identity against a discovered signed ENR, and carries each Yamux frame in an authenticated Noise record. Handshake frames are capped at 2,048 inbound bytes; each transport record carries at most 16 KiB of Yamux data plus its header.

`P2PPeer` exchanges Status and Metadata before opening a gossip stream. It routes gossip through `P2PGossipSession` and serves block and column requests on separate Yamux streams. `fetchBlocksByRoot` and `fetchBlocksByRange` return decoded blocks only after fork, request membership, order, and duplicate checks; callers still apply the consensus transition before import. `fetchColumnsByRoot` and `fetchColumnsByRange` validate every returned sidecar against its requested root or canonical slot, known block, inclusion branch, and KZG proofs before writing any returned column. The store's availability check changes to true only when all local samples are present. An unknown root returns zero chunks. Reads use a five-second deadline per request; responses are limited to 16 MiB of wire bytes and their requested chunk count. The Snappy block writer currently emits literals, so a near-limit gossip message can exceed its encoded-size cap and be rejected by `encodeGossip`.

`consensus.ENR` encodes and verifies bounded, signed IPv4 node records with the Fulu `eth2`, `cgc`, and `nfd` fields. The live service checks the fork before candidate admission and dials only the TCP address from a discovered verified record.

`consensus.DiscoveryBootstrap.Candidates` admits configured `enr:` URIs after signature and fork checks, retains at most 256 identities, and accepts only higher ENR sequence numbers for updates. `Discv5Discovery.Service.maintain` probes these candidates, retries failed probes after two seconds, and refreshes live sessions and node queries every 30 seconds.

`consensus.P2PAdmission.Admission` tracks at most 256 connected peer IDs, routes block, attestation, aggregate, and data-column bytes through the ingress validators, counts rejected messages, and blocks peers after a configurable number of invalid messages. It retains the count across disconnect and reconnect. Consensus callbacks return `error.InvalidGossip` for peer-rule rejection; local callback failures do not lower the peer score. Unknown blocks and duplicate columns do not lower the peer score. The caller provides authenticated peer IDs; this module does not establish connections or subscribe to gossip topics.

`consensus.P2PGossip.Service` decodes bounded Gossipsub subscription and publish RPCs with no new dependency. It accepts the current fork's block and aggregate topics, selected attestation subnets (0–63), and sampled data-column subnets from an optional verified store. It runs `P2PIngress` before publish delivery; columns also require a known block and parent state, a valid signature, inclusion proof, and KZG proof before retention. Remote subscriptions select connected recipients and are cleared on disconnect. Malformed protobuf, signed gossip fields, malformed SSZ, oversized payloads, wrong-fork objects, invalid columns, and `error.InvalidGossip` count against the sending peer; local failures do not. Frames are capped at 16 MiB with at most 256 subscription updates and 16 publishes, and valid duplicates are retained in a 1,024-entry cache. Mesh control remains outside the live service.

`consensus.P2PGossip.Stream` handles the [libp2p unsigned-varint message delimiter](https://github.com/libp2p/go-libp2p-pubsub/blob/master/gossipsub_peer_lifecycle_test.go) around each protobuf RPC. It buffers only one bounded RPC, accepts split or combined transport reads, and passes complete messages to `Service`. The live peer creates one stream per authenticated connection and discards it on disconnect. Invalid length prefixes count against the peer.

Send `Service.localSubscriptionFrame()` when a gossip stream opens, including after reconnect. It announces the local block and aggregate topics plus selected attestation and data-column subnets in one framed RPC. Remote peers can then select this node for those topics; no unselected subnet is announced. Local recipient selection excludes disconnected and banned peers. Aggregate gossip uses the pinned `SignedAggregateAndProof` SSZ schema and reaches the caller's consensus validator only after decoding and fork checks; the callback must verify signatures and consensus rules. For data columns, the `ColumnRoute` store and lookup must remain alive while the service runs. An unknown block returns `error.UnknownBlock` without penalizing the sender or retaining the sidecar; the caller may fetch the block and retry the same bytes.

`consensus.Discv5Messages` encodes and checks bounded, canonical PING, PONG, FINDNODE, and NODES plaintext messages. NODES replies verify every signed ENR and its current fork before exposing peers. Ordinary packet plaintext is capped at 1,193 bytes so the discv5 header and GCM tag fit the 1,280-byte UDP packet limit.

`consensus.Discv5Packets` masks and checks discv5 static packet headers and encodes/decodes the exact 63-byte WHOAREYOU challenge. Header inspection is unauthenticated; ordinary and handshake payloads require session cryptography before any message is trusted.

`encodeOrdinary` and `decodeOrdinary` authenticate ordinary packet plaintext with AES-128-GCM and the unmasked header as associated data. `consensus.Discv5Session.Session` generates unique outbound nonces and masking IVs, rejects replayed authenticated inbound nonces, and exhausts after its configured 1–4096 packet budget.

`consensus.Discv5Handshake` derives directional session keys with ephemeral secp256k1 ECDH and HKDF-SHA256 from the exact 63-byte unmasked WHOAREYOU challenge. `encodePacket` always includes the sender's signed ENR and encrypts the first message. `decodePacket` checks the ENR, fork, node ID, identity proof, and AES-GCM tag before returning plaintext or keys. An omitted ENR is accepted only with a verified cached record whose sequence matches the challenge. The caller supplies a fresh ephemeral secret, nonce, and masking IV for every handshake, consumes each pending challenge once, and maps `keys.initiator` to initiator-to-recipient traffic and `keys.recipient` to the reverse direction. Packets are capped at 1,280 bytes and embedded ENRs at 300 bytes.

`consensus.Discv5Udp.Socket` binds an IPv4 UDP endpoint, sends bounded packets to verified ENR addresses, and receives complete datagrams with a timeout. `requireEndpoint` compares an authenticated peer's signed ENR with the datagram's source address. The discovery service applies this check after the handshake proof and before installing session keys.

`consensus.Discv5Discovery.Service` binds a local IPv4 UDP endpoint, signs its ENR, and admits up to 256 configured bootstrap peers. Call `addBootstrap` with signed `enr:` URIs and drive `step` or `maintain`; explicit `probe` and `findNode` remain available. A probe receives WHOAREYOU, replies with a signed handshake PING, and becomes discoverable after an authenticated session PONG. Challenges expire after one second and are bound to both source node ID and UDP endpoint. `discoveredRecord` returns the signed TCP address. NODES replies have a ten-second deadline; request IDs, response counts, fork fields, signatures, and requested distances are checked before admission. At most 16 records are sent as one ENR per datagram.

## Running the live service

Create `P2PGossip.Service` with the caller's consensus callbacks, then `P2PService.Service.init` with that service, an identity key, an IPv4 `ENR.Local`, the candidate limit, Status, and Metadata. The four-byte Status fork digest must equal the ENR fork digest and the gossip digest; Metadata custody count must equal the ENR custody count. Port zero is allowed for both local UDP and TCP; `localUri()` returns the signed ENR with the actual bound ports. Feed `addBootstrap()` verified `enr:` URIs from configuration and call `step(timeout_ms)` repeatedly. It probes, discovers, dials, accepts, handles gossip and requests, and reconnects after socket loss. The smaller node ID initiates TCP. Call `setRoutes()` with a borrowed retained-block lookup, verified column store, and one canonical root view to serve requests. `activePeer()` exposes the validated root and range fetch methods. Close the live service before its gossip service, routes, or KZG settings.

The current service supports one simultaneous IPv4 TCP peer. Gossip and requests use distinct Yamux streams, but request calls serialize on that connection; there is no multi-peer mesh or higher-level sync scheduler. The column store must be opened with the local discovery node ID and a custody count of at least four, then backfilled for the 4096-epoch serving window before advertising full custody availability. Only custodied columns are served, while all locally sampled columns are verified before retention. The loopback tests cover both nodes; interoperability with an external consensus client has not been checked.

Run `zig build test-transition -Doptimize=Debug` for focused consensus and loopback checks, `zig build test -Doptimize=Debug` for the full suite, and repeat each command with `-Doptimize=ReleaseSafe`.

`bash scripts/test_discv5_geth.sh` starts a loopback discovery fixture and checks its signed ENR, PING/PONG, and FINDNODE/NODES exchange using Geth v1.17.10's discv5 implementation. CI runs the same check as `Geth discv5 interoperability`. This covers discovery wire compatibility with an independent implementation; Geth does not participate in Fulu consensus gossip or sidecar retrieval.
