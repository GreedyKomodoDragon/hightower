# FULU-076/077 contract creation and local token

Creation transactions and CREATE derive an address from the creator and its pre-creation nonce. CREATE2 uses the creator, salt, and initcode hash. The machine advances an opcode creator's nonce before child execution, starts a nested state snapshot, installs returned runtime code only after gas and size checks, and keeps a failed child's creator nonce and gas charge. Transaction creation advances the sender nonce before the frame. [EIP-7610](https://eips.ethereum.org/EIPS/eip-7610) storage collision checks follow the pinned Cancun oracle. SELFDESTRUCT transfers balance immediately and removes an account at transaction finalization under pre-Cancun rules or when the account was created in that transaction.

The [LocalToken artifact](../src/execution/fixtures/local_token.json) is hand-assembled EVM bytecode, with SHA-256 of initcode pinned in the file. It mints 1,000 integer units to the deployer, supports `transfer(address,uint256)` and `balanceOf(address)`, and emits the standard Transfer event. Balances use the address as a direct storage key. It is a deterministic ERC-20-like test contract, not Circle USDC or a complete ERC-20 implementation.

`zig build test-token` signs deployment and two transfers with the repository's synthetic test key, builds a canonical block through `Chain.append`, checks gas and state-root commitments, balances, statuses, receipt contract address, and the exact log in both the receipt and `eth_getLogs`. The second transfer reverts and emits no committed log. The run prints the successful event's block and transaction indexes. CI runs this step separately.

`zig build test-execution` checks twenty-two single-case JSON fixtures from the SHA-256-pinned [execution-spec-tests v5.4.0 archive](https://github.com/ethereum/execution-spec-tests/releases/tag/v5.4.0). The [manifest](../src/execution/fixtures.zig) records each case's source path and checksum. The selected cases cover transaction creation, storage, code and nonce collision, CREATE and CREATE2 return data and child revert, initcode and runtime limits, insufficient code-install gas, invalid `0xef` runtime code, initcode context, SELFDESTRUCT rollback and reentrancy, repeated CREATE2 after SELFDESTRUCT, and the Shanghai/Cancun deletion difference. The runner compares complete post-state, state root, and logs hash; six cases also pin gas used, derived from the fixture's sender balance delta and gas price. CI runs these cases in Debug and ReleaseSafe.
